# 生成模型与机器人从表示到物理可用性

## 主题结论

InstructMesh 与 Aero Hand Open 处在物理 AI 链条的两端：前者从生成 3D latent 修复制造缺陷，后者从 CAD/腱传动模型训练并部署灵巧操作策略。两者都把不可见的中间结构外置，但“可视化/可仿真”不等于“物理正确”：前者缺真实打印与完整用户研究证据，后者的拇指耦合和真实任务测量仍是主要误差源。

## 对照

| 阶段 | InstructMesh | Aero Hand Open |
| --- | --- | --- |
| 表示 | TRELLIS `64^3` sparse voxel latent | MuJoCo 16 joints/20 spatial tendons/7 actuators |
| 用户/控制接口 | 选区 + LLM prompt 或 slider | 7 motor encoder channels 与 affine/fit map |
| 验证 | 形成性缺陷 taxonomy；声称 N=12 用户研究 | 独立 cable excursion、动态 tracking、open-loop replay、cube rotation |
| 物理边界 | 静态制造几何，不处理 Fused Joints | underactuated grasp 与 in-hand rotation；不含复杂物体泛化 |
| 最大证据缺口 | 缺页导致用户研究/打印成功率不可核验 | thumb excursion mismatch、真实 pose/速率未记录 |

## 证据分层

1. **表示层**：latent voxel 或 tendon routing 是否能承载目标结构？InstructMesh 给出操作语义，Aero 给出 CAD-derived coefficients。
2. **接口层**：用户/策略是否只使用可获得信号？InstructMesh 用 preview 暴露 latent diff；Aero actor 只用七个 encoder-derived channels。
3. **执行层**：输出是否满足外部约束？应分别测 manifold、壁厚、孔径、碰撞、力和动作稳定性，而非只看渲染或仿真画面。
4. **迁移层**：换打印机、材料、物体、摩擦或磨损后是否保持？当前两篇都没有完整的跨条件矩阵。

## 研究启示

- 把 preview 连接到自动 verifier：mesh manifold/slicer/wall-thickness 检查应在 InstructMesh 的红绿 latent preview 后运行。
- 把 sim-to-real map 连接到在线校准：Aero 的 thumb cross-term 应由真实 encoder/视觉数据持续估计，而不是只靠 first-order fit。
- 统一记录 `representation → interface → external evidence → residual → repair`，这样可以比较 3D 生成的几何残差与机器人传动残差，而不会把不同层的成功率混在一起。

## 最小联合实验

1. 对 InstructMesh 的每次 edit 记录选区外 Hausdorff 距离、拓扑/壁厚检查和 slicer 结果。
2. 对 Aero 在不同 cube 质量/摩擦、thumb calibration 和 cable wear 下记录角速度、掉落率、tracking RMS。
3. 用同一表格区分作者主张、自动检查、人工/实物证据和未测条件，报告失败恢复或重新编辑成本。

# 结构化中间层与可验证执行

## 定义与边界

本主题关注一个共同设计模式：不要让基础模型直接从输入跳到最终动作或最终样本，而是引入一个结构化、可访问、可监督或可验证的中间层。这个中间层可以是 GUI transition、skill graph、工具集合、completion condition、parallel velocity block 或 object-centric 3D feature；它的价值不在于“多一个模块”，而在于把原本隐含在模型内部的关键变量外部化，从而改善选择、执行、诊断或恢复。

“可验证执行”在这里不是形式化安全证明。它至少要求系统能取得与目标状态相关的证据，并能把失败定位到表示、检索、执行或验证环节。本轮六篇论文覆盖了从 benchmark、检索、记忆、奖励、生成采样到机器人表示对齐的不同层面。

## 2026-08-03 增补：把反馈与算力放到正确的结构里

本轮五篇论文把同一设计模式扩展到两个方向：长期 Agent 需要把反馈整理成可追踪、可计算、可回滚的状态；多模态/生成模型需要把额外计算放到最有信号的层段或频段，而不是均匀铺开。

这五篇共同说明：结构化中间层的价值不只是“可解释”，而是能把资源分配问题变成可控接口。MerchantBench 和 AgentHPOBench 把长期行为拆成可审计的反馈轨迹，暴露了活动衰减、覆盖早期收益、harness 依赖等失败模式；ADAMM 把历史记忆从上下文片段变成表和工具，减少“找到了但算不出来”的错配；ReLoop 和 WaiT 则把额外计算从 token/像素的全量重复，改为对 retrieval-forming depth 或 low/high frequency schedule 的定向重复。

一个新的统一抽象是：

`persistent trace -> structured state -> operation/schedule planner -> final action/sample -> delayed outcome -> revision`

其中前三篇关注 trace 到 state 再到 decision 的闭环，后两篇关注 schedule planner 怎样把计算推迟、重复或集中到有信号的位置。它们的共同风险也相似：如果中间结构抽取错、定位错或指标错，系统会更稳定地执行错误，而不是自动变安全。

## 2026-08-04 增补：workflow route 也应成为可执行中间层

[[notes/papers/2026/08/04/Learning Compositional Meta-Routing for Agentic Workflows- An Executable Benchmark]] 把 Agent 进入任务前的“操作组合”显式化：直接答、分解、检索/工具、代码执行、委派 specialist、验证中间结果不再藏在 prompt 或 agent loop 里，而是被写成一个 route，并由 executor 真实改变任务状态后再 machine-check。

这篇论文给本主题补了一种新的中间层：`raw task text -> operation route -> executable state transition -> exact evaluator`。它的价值不在于 n-gram logistic router 本身，而在于把 workflow 选择从最终成功率中拆出来，允许同时观察 success、cost、action F1、exact-route match、budget compliance 和 typed failure。

| 论文 | 中间层 | 可验证对象 | 关键证据 | 主要缺口 |
| --- | --- | --- | --- | --- |
| [[notes/papers/2026/08/04/Learning Compositional Meta-Routing for Agentic Workflows- An Executable Benchmark]] | `{D,T,C,G,V}` operation route | executor 产物与 exact answer | 标准 test learned router 100% success、cost 1.76；one-shot 56.5%；static 93.5%、cost 3.08 | lexical-shift learned 降到 75.9%，低于 static 93.5%；executor 是 synthetic deterministic Python |

这也修正了“结构化中间层必然更泛化”的直觉。route composition 在标准 split 上很强，但 lexical router 会漏掉 aggregate code、multi-hop decomposition 和 conflict verification。也就是说：中间层可验证，只是让失败更可定位；它本身不保证泛化。下一步更合理的系统设计是 semantic router + uncertainty/static fallback + observation-conditioned replanning。

## 共同机制

### 1. 把“正确答案”改写成可检查对象

- DDB 不只问“点击哪里”，而是把 GUI 的 state transition 和 decoy transition 分开，测试模型是否理解动作造成的变化（Sections 2–3，pp. 2–5）。
- IRA 先让模型提出 completion conditions，再让它调用系统、应用和 GUI 工具逐条取证；reward 不再只依赖轨迹文本或最后截图（Sections 3–4，pp. 3–7）。
- SAM3D-VLA 把“关注哪个对象、对象是什么几何结构”写成 mask 和 teacher feature target，而不是让 π0 隐式猜测（Eqs. 3–5，pp. 4–5）。

这三个系统都把 final answer 改成了 `state claim → evidence/representation → action or score`。差别在于 DDB 是评测对象，IRA 是执行时验证器，SAM3D 是训练期监督。

### 2. 把组合结构显式化

- HiSkill 把历史轨迹提炼为 skill/AtomicOp graph，support/recovery edge 让执行既能复用成功程序，也能沿恢复路径脱困。
- HYSET 把工具选择从 independent top-k 改成 query-conditioned hyperedge prediction；`F_set` 和 cardinality-specific `M_m` 直接表达互补性（Eqs. 1–14，pp. 1–8）。
- PDD 把串行采样轨迹拆成 block 内多条 mean-velocity 输出，再在推理时 fused；并行不是简单复制 rollout，而是训练一个可共享多种 NFE 的中间向量。

组合结构的共同收益是减少“局部最相关但整体不可用”的决策：重复工具、重复动作、重复 denoising step 都可能看起来合理，却不能完成全局目标。

### 3. 训练期重监督，部署期轻接口

PDD、SAM3D-VLA 和 IRA 都出现了“昂贵 teacher/verifier 不一定进入最终路径”的设计：PDD 的 teacher flow 只用于蒸馏，SAM3D/SAM2/detector 只用于训练，IRA 的验证工具用于打分或 RL 而不是替换 GUI policy。这个模式能降低部署依赖，但会把风险转移到三处：teacher/evidence 是否与真实目标一致、训练分布是否覆盖失败、以及蒸馏后的中间层能否在缺少 teacher 时保持校准。

## 一个统一的闭环抽象

可以把六篇论文放进下面的执行链：

`query/instruction → structured proposal → execution → evidence/state delta → verifier/reward → recovery or update`

- **structured proposal**：HYSET 选工具 hyperedge，HiSkill 选 skill graph path，SAM3D 生成 subtask-object mask，PDD 选择 block/NFE。
- **execution**：ToolLLaMA/LLM agent 调工具，GUI agent 施加 click/key，π0 输出动作，生成模型执行 block update。
- **evidence/state delta**：DDB 的 GUI delta、IRA 的 artifact/hidden state、SAM3D 的 object feature、PDD 的 teacher trajectory。
- **verifier/reward**：IRA 是最直接的 verifier；DDB 是离线 transition evaluator；HYSET 用 execution feedback；PDD/SAM3D 主要在训练期用 teacher loss，而非部署期验证。
- **recovery/update**：HiSkill 的 recovery edges 最明确；IRA 的 RL reward 试图把验证反馈变成策略学习；其余论文尚未形成闭环恢复机制。

这个抽象也暴露了缺口：六篇论文没有一篇同时报告 proposal quality、执行成功、状态证据正确性、恢复成功、端到端 latency 和总成本。

## 关键判断

### 证据支持的判断

- **结构化中间层是有用的归因接口。** 当一个系统把“选了什么、发生了什么、为何算成功”写成集合、图、delta 或 mask 时，更容易做 component ablation 和失败诊断。HYSET 的集合级消融和 IRA 的 state-type 拆分是本轮最强实例。
- **训练期 teacher / 部署期轻接口是现实的工程折中。** SAM3D-VLA 的 RGB-only inference 和 PDD 的 fused head 证明可以把复杂监督压缩进模型，但必须同时测量训练成本和蒸馏后的分布外退化。
- **恢复结构比单次成功率更接近 Agent 能力。** HiSkill 的 recovery edge 是显式结构；DDB 显示 context 对 decoy identification 有帮助但可能伤害 exact match，说明“更多上下文”不等于更可靠，需要状态条件化的恢复策略。

### 尚未被充分支持的判断

- **“可验证”不等于“真实正确”。** IRA 的 ground truth 仍是 task-specific scripts，HYSET 的 gold tool set 可能非唯一，SAM3D 的 teacher target 也依赖自动 mask；验证器或 teacher 自身错时，结构化中间层会把错误固化。
- **“并行/压缩”不等于端到端更快。** PDD 没有 latency，HiSkill 没核算离线 skill 构建，IRA 的验证 token 很高；必须用统一 TCO 而不是单项 NFE/token 数比较。
- **表示对齐的增益来源尚不清楚。** SAM3D 的性能提升可能来自 mask-conditioned attention；PDD 的质量提升可能来自更强的 chosen checkpoint 或 CFG 调参；这些都需要 matched ablations。

## 2026-08-06 增补：视频理解里的 latent route 也是中间层

[[notes/papers/2026/08/06/Perception Before Reasoning- Dynamic Latent Reasoning for Video Understanding and Question Answering]] 把中间层从显式工具/图/状态进一步推进到视频模型内部的 latent route：perception latents 负责 grounding，reasoning latents 只在题目需要时展开。它说明“结构化中间层”不一定非得是外部对象，也可以是可切换、可监督的内部过程。

| 论文 | 中间层 | 可验证对象 | 关键证据 | 主要缺口 |
| --- | --- | --- | --- | --- |
| [[notes/papers/2026/08/06/Perception Before Reasoning- Dynamic Latent Reasoning for Video Understanding and Question Answering]] | perception / reasoning latent route | 视频 QA 的答案与可见 token 预算 | Qwen3-VL-4B 54.0 -> 58.2，同时 token 1220.7 -> 18.5；w/o grounding / reasoning / routing 都掉分 | latent 过程不直接可读；只测 4 个 open-source backbone；总 FLOPs 未充分对齐 |

这篇和 `See2Think` 的共同点是：都在回答“模型是否真的用到了中间视觉状态”；差别是 `See2Think` 用干预检查状态是否被采用，而 DyLaR 直接把中间状态做成了可学习的 response route。前者偏诊断，后者偏构造。

## 复现优先级

1. **HYSET（最高）**：代码、ToolBench mirror、3 seeds 和消融都较完整。先复现 annotation-only Full / w/o `F_set` / Set Transformer，再加入 execution feedback，记录 false negative 和 judge 成本。
2. **IRA（高）**：实现一个 artifact/hidden-state/visible-state 的最小 verifier，固定 verification budget，做阈值、条件权重、tool mutation 和 reward-to-policy 对照。
3. **DDB（高，评测先行）**：扩展 workflow/平台并加入 human ceiling、标注一致性和 action payload metric；它能验证 GUI transition 是否真的比 screenshot matching 更能预测成功。
4. **SAM3D-VLA（中高）**：先做 LIBERO-Long 的 mask-only、2D teacher、SAM3D teacher 和随机 teacher 四臂归因；没有这些消融，不建议直接上 8×H100 真实机器人。
5. **HiSkill（中）**：在一个 GUI 或工具调用环境接入 graph/recovery，单独核算离线轨迹采集、skill extraction、index build 和 online tokens。
6. **PDD（中）**：从 ImageNet 小 teacher 开始，以真实 latency/显存/seed 方差为首要指标；再考虑大模型 data-free 设置。

## 待追踪问题

- [ ] 能否用同一套 `proposal → execution → evidence → recovery` schema 评测 GUI、tool-agent、机器人和生成模型，而不把 reward/judge 细节混在一起？
- [ ] 当 gold set/condition/mask/teacher 不是唯一或可能错误时，如何表示等价解、置信度与 provenance？
- [ ] 怎样统一训练摊销、在线 token、tool/judge call、GPU latency、机器人执行时间的端到端 TCO？
- [ ] recovery edge、IRA verifier 和 DDB transition delta 能否形成可学习的 failure taxonomy，并指导下一次动作？
- [ ] PDD 的 adaptive block size 与 IRA 的 verifier 是否可以组合：按局部置信度决定生成 NFE，而不是固定预算？
- [ ] SAM3D 的 object-centric target 与 HiSkill 的 subtask skill 是否能共享对象状态接口，支持跨任务迁移？

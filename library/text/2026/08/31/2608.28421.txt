Symbolic Backpropagation for Post-Training LLMs

Abstract
Post-training a language model to reason means updating its weights. Supervised fine-tuning and reinforce-
ment learning both place the acquired capability inside the model, where it cannot be inspected, cannot be
checked step by step, and cannot be moved to another model. We argue that for tasks whose intermediate
steps admit verification, reasoning is better placedoutsidethe base model’s weights, as an explicit program
composed from deterministic and neural primitives. We introduce PLVR (Program Learning with Verifiable
Rewards), a post-training method that learns such programs directly from input–output examples. Its
mechanism issymbolic backpropagation: each program layer carries a typed ontology, a loss is computed
at the output against ground truth, and required input ontologies are propagated backward by type inference
over primitive signatures—an analogue of the chain rule in which credit assignment is a derivation rather
than an estimate. Where RLVR verifies a terminal outcome, PLVR’s reward is a per-step contract verdict,
dense over program structure. On LiveCodeBench v6 and τ 2-Bench, ≈30B base models with PLVR
outperform RL at matched budget by 27.8 points on average, and frontier models an order of magnitude
larger by 13.6 points. A single primitive library serves two benchmarks, so the marginal cost of a new
task is ≈100 examples of program search and no new fine-tuning data; identification of the best available
program is reliable within seventy. Replacing the loss-guided search with uniform sampling over the same
type-admissible space, at equal budget, collapses the median program from 65.6% to 17.5%, identifying
the backward pass rather than the type system as the source of the advantage. We release the symbolic
backpropagation library and a conformance checker so the method can be applied to primitive libraries
other than our own.
1 Introduction
Post-training has converged on a single locus. Supervised fine-tuning adjusts weights toward demonstrated behaviour;
reinforcement learning adjusts them toward rewarded outcomes (Guo et al., 2025). Both store what was learned in the
same place it was already stored, and inherit three properties of that choice. The acquired capability is opaque: nothing
in the weights says which step of a multi-step task the model now performs better. It is unverifiable in progress: a
trajectory can only be judged once complete. And it is bound to one model: capability learned for a 12B checkpoint
does not transfer to a 30B one without repeating the procedure.
For a large class of tasks, none of this is necessary. Agentic tool-calling, policy-constrained dialogue, and program
generation all decompose into steps whose intermediate outputs can be checked—a tool call either matches a signature
or does not, a derived task list either covers the request or does not, an ordering either respects declared dependencies or
does not. Where such checks exist, the reasoning that composes those steps can live in an explicit artifact rather than in
weights.
Reasoning outside the base model.We take this position concretely. Areasoning programis a composition of
primitives—some deterministic, some small fine-tuned language models—arranged by a typed domain-specific language,
where every primitive carries an output contract enforced at execution. The base model is not updated. What is learned
is the program: which primitives, in what arrangement, with what parameters.
This raises the question the rest of the paper answers. Gradient methods learn because backpropagation assigns
credit through a differentiable composition. A program of discrete, partly symbolic primitives is not differentiable,

Symbolic backpropagation.Our answer is that in a typed, contract-verified program, credit need not be estimated at
all. A program is organised into N layers, each carrying an ontology: a structured, typed representation of the state at
that point, and an inspection point in the sense of a debugger breakpoint. A forward pass produces an output ontology,
compared against ground truth by a loss that treats each object as a separate axis and orders type errors strictly before
value errors.
The backward pass then propagatesrequired ontologiesrather than gradients. Given the ontology required at layer
k and the declared signatures of the primitives, the compositions that could produce it induce, by type inference, the
ontology required at layer k−1 . That derived requirement plays the role the upstream gradient plays in the differentiable
case. Type resolution is deterministic; only the search over parameter values within each primitive’s declared range is
not. Contract verdicts prune this search and localise failure to the step that produced it.
Verifiable rewards, densified.The relationship to RLVR is direct. RLVR replaced learned reward models with
programmatically verifiable outcomes—a signal checked rather than modelled. That signal remains terminal and scalar:
it reports that a trajectory succeeded or failed, not where it went wrong. PLVR extends verifiability inward. Every step
carries a typed output contract, so correctness is checkable at each step. The reward is verifiable in RLVR’s sense—no
learned model, checked against a specification—but dense over the program’s structure rather than sparse over its
trajectory.
Scope.The method applies where intermediate outputs admit checking. This is a precondition entailed by the
mechanism, not a limitation discovered after the fact: contracts that localise failure require checkable outputs. Tasks
whose quality is a matter of judgement rather than satisfaction—summarisation, open generation—remain the domain of
gradient post-training, and we make no claim about them. We compare only against reinforcement-learning post-training,
which is the stronger target, and make no claim relative to supervised fine-tuning.
Contributions.
• Symbolic backpropagation, a credit-assignment procedure for compositional neural programs in which required
input ontologies are derived backward by type inference over primitive signatures rather than estimated from
rollouts. Types resolve deterministically; value search is bounded by declared ranges.
• PLVR, a post-training method built on it, alternating program search under frozen primitives with primitive
retraining under a fixed program. The base model’s weights are never updated.
• Evidence that program learning outperforms RL post-training at matched budgeton two benchmarks with
distinct verification characters—LiveCodeBench (Jain et al., 2024) (execution against tests) and τ 2-Bench (Barres
et al., 2025) (constraint satisfaction over dialogue), the latter across three domains—against vanilla prompting, a

and on parameter count respectively.
• An ablation isolating the mechanism.Replacing the loss-guided search with uniform sampling over the identical

2 Related Work
2.1 Post-training and verifiable rewards
Supervised fine-tuning and reinforcement learning are the two established routes to improving a model’s reasoning.
RLHF trains against learned reward models fitted to human preferences (Christiano et al., 2023; Ouyang et al., 2022).
Reinforcement learning with verifiable rewards (RLVR) replaces the learned reward model with a programmatic check—
answer matching for mathematics, execution for code—removing a component that could be gamed and a source of
reward hacking. DeepSeek-R1 develops extended chain-of-thought, reflection, and self-verification through large-scale
RL over such rewards (Guo et al., 2025).
We share RLVR’s premise that a reward one can check is preferable to one that must be modelled, and extend it
in a single respect: the verifiable signal in RLVR is terminal and scalar, reporting that a trajectory succeeded or failed
rather than where it went wrong. In PLVR the signal is a typed output contract at every step, verifiable in the same
sense and dense over the program’s structure. The base model’s weights are not updated at all; what is learned is an
explicit program together with the weights of the small primitives it invokes.
2.2 Process supervision and step-level verification
The limitation of terminal rewards is well recognised. Process supervision provides step-level rather than outcome-level
feedback, and process reward models (PRMs) trained on step-wise labels improve reliability over outcome reward
models (Uesato et al., 2022; Lightman et al., 2023). Subsequent work reduces the annotation burden through automated
label construction (Wang et al., 2024) and extends PRMs to agentic settings, where—unlike mathematical reasoning—the
correctness of an individual action is not clear-cut and must be estimated from eventual outcomes (Xi et al., 2025). A
recent line trains step-level verifiers using formal verification tools rather than human annotation (Kamoi et al., 2026).
This is the nearest work to ours on the axis of signal density, and the distinction is precise. A PRM is alearned
verifier: a model that judges steps, requiring step-level supervision to train and inheriting the same gameability and
opacity that RLVR removed at the outcome level. A contract in PLVR is aprogrammaticcheck derived from a
primitive’s declared type signature. It requires no step-level annotation, it is checked rather than predicted, and where
the check is structural it is exhaustive. In short, PRMs extend rewardmodellingto the step level; we extend reward
verificationto the step level.
2.3 Backpropagation through compound AI systems
A substantial line of work carries the backpropagation metaphor into systems built from LLM calls. ProTeGi introduced
natural-language gradients for prompt search (Pryzant et al., 2023). TextGrad formalises this into an end-to-end
framework in which a computation graph over text variables is optimised by backpropagating LLM-generated cri-
tiques (Yuksekgonul et al., 2024). Trace generalises the idea to execution traces under the OPTO formalism (Cheng et al.,
2024). GEPA shows that reflective prompt evolution using natural-language feedback can outperform reinforcement
learning while requiring far fewer rollouts (Agrawal et al., 2026).
Our method shares the metaphor and differs in what the backward signalis. In every system above, the gradient
analogue is text produced by a language model: a critique, a suggestion, a reflection. It is therefore stochastic,
unverifiable, and subject to the degradation with depth that motivates the analyses cited. In PLVR the backward signal
is arequired ontologyderived by type inference over declared primitive signatures, together with contract verdicts that
localise failure to the step that produced it. Nothing in the backward pass is generated; the required input follows from
the signatures. This is the sense in which credit assignment here is a derivation rather than an estimate, and it is why the
analogue does not degrade with depth in the way textual feedback does.
We note that GEPA’s thesis—that language provides a richer learning medium than policy gradients derived from
sparse scalar rewards—is close to our own diagnosis of why gradient post-training is weak on multi-step tasks. We differ
in the remedy: GEPA searches over instructions guided by reflective feedback, while we obtain per-step attribution
structurally, from types and contracts.

2.4 Declarative pipelines and workflow synthesis
DSPy abstracts LM pipelines as parameterised modules compiled by an optimiser over prompts and demonstra-
tions (Khattab et al., 2023). A more recent line searches over pipelinestructurerather than pipeline text. ADAS treats an
agent as a program and uses a meta-agent to propose, execute, and retain high-scoring designs (Hu et al., 2025). AFlow
reformulates the problem as Monte Carlo tree search over code-represented workflows in which LLM-invoking nodes
are connected by edges, refined through code modification and execution feedback (Zhang et al., 2025). AgentFlow uses
reinforcement learning to construct workflows that dynamically select tools from a predefined set (Li et al., 2026).
These share our interest in explicit, searchable program structure. They differ in two respects. First, their optimisation
signal is a coarse scalar score over whole trajectories; ours is a per-object loss with per-step contract attribution. Second,
they optimise structure over untyped LLM calls without verification of intermediate semantic outputs, whereas our
primitives carry typed contracts enforced at execution.
2.5 Neurosymbolic reasoning with language models
Logic-LM and Proof-of-Thought delegate reasoning to symbolic solvers or theorem provers, in domains with clean
formal semantics (Pan et al., 2023; Ganguly et al., 2024). SEVerA pairs first-order-logic contracts with verified fallback
mechanisms (Banerjee et al., 2026).
Agentic tool-calling does not. Intent coverage and function matching are semantic judgements that resist complete
formal specification. PLVR therefore splits the problem rather than choosing a side: deterministic mechanisms enforce
structural invariants through typed composition and execution guards, while learned primitives handle the semantic
decisions, bounded by contracts that are empirically validated rather than proven. Our use of “verification” throughout
denotes contract checking plus empirical validation, not end-to-end formal correctness, and we state this explicitly rather
than allowing the term to carry more weight than the method supports.
3 Methodology
A PLVR program is a composition of primitives arranged by a typed DSL, organised into N layers. Each layer carries
anontology: a structured, typed representation of the state at that point in the computation. Learning a program means
determining, for each layer, which primitives and operators produce the ontology the next layer requires.
We describe the representation (§3.1–3.4), the loss over ontologies (§3.5), the backward pass that propagates required
ontologies by type inference (§3.6), and the alternation between program search and primitive training (§3.7).

Objects nest, so an ontology carries both type structure and instance values for the example being processed. We use the
term in the knowledge-representation sense—classes and relations—with the qualification that a layer’s ontology is
populated: the same object carries its type and the values realised on this input.
Ontologies enter and leave the program through a pair of tokenizers, described in §3.2.
A program is a sequence of N layers. Every layer is initialised as pass-through, and each is an inspection point:
at any layer the ontology can be read directly, giving the intermediate state of the computation in the same sense a
debugger breakpoint gives the state of a running program. This is a property of the representation rather than an added
instrumentation—the ontologyisthe state.

This uniformity is what makes the layer stack coherent. Every layer, including the first and the last, carries an
ontology of the same kind, so the loss (§3.5) applies unchanged at the output boundary and at the input boundary (§3.6),
and a primitive that consumes a type does not care whether that object arrived from the instance, from an intermediate
layer, or from an answer being scored.
The tokenizer plays the role a subword tokenizer plays for a transformer, converting between the external representa-
tion and the units the system computes over. It is hybrid: a learned component identifies structure in unconstrained text,
and symbolic components check that the structure found is well-formed and grounded. Henceneurosymbolic.
Contract.Largely deterministic, and identical in kind at both ends. Every object must conform to a declared type in
the schema. Where a schema declares an ordering, indices must be contiguous and strictly increasing—an ontology is a
keyed collection, so sequence survives as data rather than as position. Cross-references must resolve: a tool call in an
assistant turn must name a tool present in the registry, and a call’s bindings must type-check against the signature of the
function named. Where a declared type carries a formal language, its values must parse and type-check in it.
The constraint that matters most is that every text field must be a verbatim span of its source. Nothing may be
paraphrased or invented at the boundary. Only semantic attribution—which speaker a turn belongs to, which action an
answer expresses—is validated empirically.
Why the boundary matters.The tokenizer determines what the loss can see. An error it makes on the instance is
invisible to every downstream contract, because the ontology it produced is what the program takes as ground truth about
its input. This is why the verbatim-span constraint is deterministic rather than empirical: it is the one place a learned
component could silently introduce content that nothing downstream would catch. At the other end, the tokenizer fixes
the granularity of the loss—objects it does not distinguish cannot be scored separately, and objects it fabricates are
penalised as spurious.
3.3 Primitives
A primitive is a leaf that computes. Each is narrowly scoped, pure (stateless and side-effect-free), carries a declared
input/output type signature, and carries anoutput contract: an explicit specification its result must satisfy.
Primitives are symbolic or neural. Symbolic primitives have semantics expressible as a formal program and are
correct by construction with respect to their specification. Neural primitives are small language models fine-tuned on a
single operation; restricting each to one operation follows the empirical property that reliability is inversely related to
task scope.
A primitive isfirst-order: it consumes and produces ontologies and does not take a composition as an argument.
This is the rule that separates primitives from operators (§3.4), and it is why a primitive can carry an output contract at
all—it has a result of its own to check.
The library used throughout this work contains 10 primitives: DECOMPOSE, ELABORATE, INIT-SCRATCHPAD,
GET-ORDER, DENOTE, CHECK-PREREQUISITES, MATCH, IDENTITY, WRAP, and APPEND. We group them by role
rather than by capability, which is what makes the set principled rather than fitted to a benchmark:
• Lifting.DENOTEmaps text to a formal representation in a fixed target language; ELABORATEexpands terms
using a fixed dictionary. These bring unconstrained input into the regime where contracts apply.
• State.INIT-SCRATCHPADseeds a monotone store from configuration; CHECK-PREREQUISITESevaluates a
three-valued condition against it.
• Structure.DECOMPOSEderives an ordered task list; GET-ORDERproduces a dependency-respecting permutation.

Contracts span type constraints (a valid object conforming to a schema), value constraints (extracted entities must

levels of assurance.Deterministiccontracts are checked exhaustively and guarantee the specified property.Empirical
contracts—those on neural primitives—detect outputs violating an expressible condition but do not prove that every
contract-satisfying output is correct. Our use of “verification” throughout denotes contract checking plus empirical
validation, not formal correctness.

3.6 Symbolic backpropagation
A forward pass executes the program and records each layer’s ontology, producing a loss at the output. The backward
pass propagatesrequired ontologies.
Given the ontology Ωreq required at layer i, thesynthesis stepproduces a ranked set of compositions that could yield
it, each paired with the input ontology that composition would require at layer i−1 . That derived requirement becomes
Ωreq for the next synthesis step, playing the role the upstream gradient plays in the differentiable case.
The step resolves types before values.

whose declared output type unifies with type(o); monomorphic primitives require exact match, polymorphic operators
unify with any type and propagate the instantiation to their required input. Where no single primitive covers Ωreq,

Value resolution.Free parameters are enumerated across the composition and restricted to their declared ranges,

This is the sense in which credit assignment is a derivation rather than an estimate. Type resolution is deterministic—
the required input follows from the signatures—and only the search over values within declared ranges is not.
Scoring and truncation.Candidates are executed on the example through the already-synthesised layers and scored
against ground truth, not against Ωreq alone: a composition that hits its local target but leads to a worse end result must
rank below one that approximates it and ends better. Compositions behaviourally equivalent to IDENTITYon the trace
are canonicalised and deduplicated. The beam retains the top k programs globally—across all programs seen, not per
layer—which bounds growth that would otherwise be exponential in depth.

the example. Compositions requiring objects that Ω0 does not supply are eliminated by the availability filter, which is
exact at this layer rather than heuristic. A candidate that survives is executable end to end.
The loss measured is output-side only. We do not currently score the residual between a candidate’s derivedΩin and
Ω0; unsatisfiable candidates are filtered rather than penalised. A per-layer input-residual term would give the search a
graded signal for how far a composition is from closing, rather than a binary one, and we note it as an available extension
that the present results do not use.
3.7 Training loop
Examples are processed one at a time: forward pass, loss, backward pass, with the surviving top-k programs carried to
the next example. Pruning is oncumulativescore across all examples seen so far, not on the current example alone, so a
program that suits early examples and fails later ones is displaced rather than retained.
Program search and primitive training alternate in phases. Primitives are frozen during search, making each phase’s
search a stationary problem and cumulative scoring meaningful. Between phases, the backward signals—the per-step
required ontologies and the contract violations localised to specific primitives—supply training targets, and the neural
primitives are fine-tuned. After retraining, the surviving beam is rescored under the new primitives before the next phase
begins; carrying old scores forward would rank programs by the performance of primitives that no longer exist, and
retraining improves precisely the primitives that were failing.
Mean beam loss before and after each retraining phase gives the convergence curve, and provides a stopping rule:
halt when a retraining phase no longer improves it.
The base model is never updated. What is learned is the program—the composition and its parameters—together
with the weights of the small neural primitives it invokes. Capability therefore resides in an inspectable artifact and in a
set of independently verifiable, independently retrainable components, rather than entangled in the weights of the model
being served.
Hyperparameters. N (layers), k (beam width), dmax (composition depth), and other hyperparameters appear in
Appendix A.

4.3 Primitive fine-tuning

4.7 Protocol
Runs and statistics.Every arm is run 3 times. For the arms we train or search — vanilla prompting, the token-matched
harness, and PLVR — repetitions vary the inference and search seeds.
The post-training baselines are published checkpoints (§4.5), so there is no training seed for us to vary: their
repetitions measure inference variance only, and we do not present their intervals as though they characterised training
variance. This is the price of not training baselines ourselves. We pay it deliberately: a baseline whose hyperparameters,
data, and stopping point we did not choose cannot be accused of having been under-trained, and that objection is the one
most damaging to our claim. Where a checkpoint’s own authors report a benchmark we also evaluate, we give both their
figure and ours, so any discrepancy in harness or decoding settings is visible rather than absorbed.
All arms share the same problem order and the same τ 2 user-simulator seeds, so comparisons are paired. Seeds are
fixed a priori and reported.
Our effective sample size is problems, not seeds. We therefore report bootstrap confidence intervals over problems
as the primary interval and give individual run numbers in Appendix C; a standard deviation estimated from three points
is not informative and we do not present one as though it were.
Inference settings for baselines.Checkpoints are evaluated through official provider APIs where available, rather
than self-hosted, to avoid performance loss from quantisation or other serving-side optimisations.
Compute accounting.A composed program spends more inference tokens than a single forward pass, and its
primitives are separately fine-tuned from bases of three different sizes (§4.3). We report total parameters, active
parameters, and inference tokens split into input and output, rather than the unit that flatters us. Active parameters vary
with which primitive is executing, so we report the range and the trace-weighted mean. Input tokens dominate, since
context is re-sent to each primitive; we report the ratio and state whether caching is used.
For the baselines we report the training scale their authors published — corpus size, hardware, and duration
where given — rather than re-deriving it. Those figures are what make the data-matched and parameter-matched
distinctions (§4.5) checkable rather than asserted, and a baseline whose training scale is undisclosed is not usable for
either comparison, which is why our selection was constrained to checkpoints that report it.
We do not attempt FLOP-matched comparison. Making training FLOPs comparable across seven heterogeneous
fine-tunes, a program search, and three externally trained checkpoints on schedules we did not control is not something
we can do correctly, and a wrong FLOP figure is worse than none. We report the raw components instead — GPU-hours
for primitive fine-tuning, candidate evaluations during program search, and each baseline’s published training scale —
and leave the conversion to the reader.
We do not report latency. It is dominated by deployment optimisation rather than by method, and this is not a latency
paper; token counts and memory footprint are reported instead.
Pre-registration.The random-sampling null (§5.5) was specified before it was run. Three choices were fixed in

5.3 Convergence and identification
Let p∗ denote the program with the best score measured on all 109 examples: 81.6% accuracy at 0.355 loss. Convergence
means that the criterion, ranking on aprefixofnexamples, eventually placesp ∗ in its leading class.
Figures 1 and 2 (§4.6) report both quantities against n; exact per-checkpoint values, including P(p ∗ ∈top-1) , are in
Appendix B. Averaged over permutations, identification is reliable fromn= 70 : the leading class contains p∗ in every
ordering, and the 5–95% band collapses to a point.Program search converges on this task within seventy examples,
and we report that figure rather than the length of any single run.
Accuracy converging is not identification succeeding.The two are routinely conflated, and separating them is the
reason we report P(p ∗) rather than accuracy alone. In the unshuffled run, top-1 accuracy reads 81.4% from n= 10
onward and never moves—but the leading class does not contain p∗ until n= 100 . Throughout that range the criterion
was leading with adifferentprogram of nearly identical score. An accuracy curve would have shown convergence at
n= 10; identification had not occurred.
The two figures therefore measure different things and both are reported: 70 examples for identification averaged
over orderings, and 100 for the unshuffled run. Averaged over 109 permutations that ordering is revealed as unlucky
rather than typical, which is why the shuffled distribution is the primary result and the unshuffled run appears only as an
illustration. Reporting one training order would have overstated convergence speed on accuracy and understated it on
identification.
A non-monotonicity worth noting. P(p ∗) dips from 0.73 at n= 5 to 0.62 at n= 10 before climbing. At very
small n many programs tie, so a wide leading class contains p∗ byinclusionrather than by discrimination. As evidence
narrows the class, p∗ is briefly excluded before being placed back on merit. Early membership and late membership do
not mean the same thing.
5.4 Discovery continues after best-in-pool plateaus
We initially expected that once best-in-pool accuracy saturates, the search has stopped contributing and subsequent
changes are re-ranking of an effectively frozen candidate set. This is false, and the distinction matters for how many
training examples are worth collecting.
The 13 behaviours discovered during this run are first seen atn= 1,1,1,5,5,7,12,12,15,33,47,47,57 . Discovery
continues to the end of training. Of the 15 changes to the leading indifference class, 4 are newly discovered programs
enteringit—at n= 5,7,12,33 —and 11 are re-rankings of programs already in the pool. Roughly 27% discovery, 73%
re-sorting.
Nothing better is found after n= 5 andnothing competitive is found after n= 5 are different claims, and only the
first holds. A program first discovered at example 33 entered the leading class immediately on discovery.
This also qualifies the training-curve analogy. The leading class improves non-monotonically—15 accuracy points
gained across 6 local decreases—and that is not purely estimator noise over a fixed candidate set. The candidate set
grows underneath the ranking, the way an SGD iterate moves under a changing gradient estimate. Both mechanisms are
active, and a plot of class quality should distinguish them rather than attributing the movement to one.

5.6 Transfer to unseen examples
The transfer study uses a separate pool drawn from BFCL (Patil et al., 2025) and LiveCodeBench rather than τ 2-Bench.
The program selected on 60 examples was re-scored on a 109-example pool of which 73 were never seen during selection
(42 BFCL, 31 LiveCodeBench). The pool, ranking, and winner were fixed before those examples were scored; nothing
was tuned on them. Scoring is identical—real execution fromΩ 0, full test suites, 15 s timeout.
The selected program is
{Scratch←INIT-SCRATCHPAD, Text←ELABORATE, [Text]←DECOMPOSE}
{[Code]←WRAP(DENOTE), [ToolCall]←FOREACH@0(MATCH)}
Accuracy falls 4.7 points from 82.3% in-sample to 77.6% held-out. The substantive question is whether that drop is
selection bias—the program having been fitted to its selection set—or a difficulty difference between the sets. It is the
latter, and the pool provides the control.
Every program in the pool drops 7–8 points on the held-out set, so the winner’s drop tracks the pool’s rather than
exceeding it. The cause is visible in the problem families: the in-sample LiveCodeBench examples are entirely AtCoder
Beginner Contest problems (abc374–378), while the held-out set adds abc379–386 together with arc184, arc185, arc186,
and arc188—Regular Contest problems, a harder tier.
Tool-calling transfer is better than the pool’s.On BFCL the selected program goes 74.7% → 74.6%, a drop of 0.1
points, where the pool average drops 8.3. Selection on 60 examples returned a program markedly more robust on unseen
tool tasks than the average candidate—the opposite of the overfitting one would expect from selecting on a small set.

A single output layer covering Ωout ={[ToolCall] , [Code]} admits 533×248 = 132,184 plans. Each
demands 5–7 input types (median 6), each independently satisfiable in 102–103 ways, so serving one layer-4 plan
requires a median of 2.7×10 9 layer-3 plans. Compounding over four layers gives on the order of 1027 type-correct
four-layer programs. The search scored roughly 14,400 candidates and retained 213—about10 −23 of the space.
1027 well-typed programs is not a tractable space by any construction. What makes the search finite is thelayer-wise
beam: eight partial programs survive each depth, so the branching factor is beam width times max plans per layer
rather than the full product. Types make each layer’s candidateswell-formed; the beam makes the searchfinite. These
are separate jobs and the first should not be credited with the second.
Availability prunes only at the bottom.With layers still to build, a required type counts as reachable if anything in
the library could produce it, so nothing is cut. Only at layer 1—where layers below is zero and the program must
close against Ω0—does the filter bite, and there it is severe: 25× on [ToolCall], 19× on Scratch. Closure, not
typing, is the binding structural constraint, and it applies last.
Width dominates depth.Increasing dmax grows candidates per key polynomially; increasingwidthmultiplies keys. A
layer demanding six types multiplies the space by roughly 109 regardless of dmax. This is why max plans dominated
the run’s cost—raising it from 60 to 200 made the first phase unfinishable—while dmax = 3 remained affordable
throughout. A practitioner budgeting this search should spend on depth before width.
6.2 Two readings the tables invite, and which one survives
Best-of-N understates the null result.Table 4 shows the gap narrowing from 40.2 points at N= 5 to 7.6 at N= 60 ,
and read on its own that trajectory suggests the guided search buys efficiency which enough random draws would
eventually recover. It does not, and the convergence is an artefact of the comparison rather than a property of the method.
The null’s pool holds 64 programs; atN= 60 it has drawn 60 of them and is exhausting its good tail. Any best-of-N
curve over a finite pool converges to that pool’s maximum, so the closing gap measures pool size, not search quality.
Table 5 is not subject to that reading. A median of 65.6% against 17.5%, with 45% of the guided pool clearing 70%
against 2% of the null’s, is a statement about where in the space each procedure lands rather than about how many draws
it takes to find one good program. A fortunate draw can produce a best-of-N gap; it cannot move a median across 213
and 64 programs respectively. We therefore treat the distribution as the primary evidence and the best-of-N table as
supporting, and we would draw the same conclusion from the distribution alone.
The transfer result says something about the loss, not the search.The most surprising number in Section 5.6 is not
the 4.7-point headline drop but the 0.1-point BFCL drop against a pool average of 8.3. The selected program is not

Selection on 60 examples might reasonably have been expected to return a program fitted to those examples,
degrading at least as fast as the pool on unseen ones. It returned the opposite. Since every arm in this paper ranks
candidates under the same loss, and only the proposal mechanism varies, this is evidence about the ranking criterion
rather than about the derivation: type errors ordered strictly before value errors, with content alignment, appears to
prefer programs whose correctness is structural rather than incidental to the examples at hand.
We flag this as an observation rather than a claim. We did not design an experiment to test it, a single selected
program on one benchmark is thin evidence, and the LCB half of the same table shows the winner tracking the pool
rather than beating it. Establishing that a lexicographic type-first loss systematically selects for robustness would require
varying the loss with the search held fixed—the one ablation this paper does not run.
6.3 What the results support, and what they do not
The null result establishes that the loss-guided search populates a qualitatively different region of the program space than
uniform sampling over the same admissible set: not a faster route to the same programs, but a different distribution. The
convergence result establishes that identification of the best available program is reliable within seventy examples, and
that this is distinct from—and slower than—accuracy appearing to plateau. The transfer result establishes that selection
on 60 examples does not overfit, with the winner’s degradation tracking the pool’s and its tool-calling performance
holding almost exactly.
Three limits are worth stating plainly. The held-out split is not i.i.d., so we report a difficulty effect rather than
a generalisation gap. The loss function and the backward pass are held fixed across all arms and are not separately
isolated; what we have shown is that target-directed derivation beats other proposal mechanismsunder this loss, not that
the loss design is independently responsible. And a program well-typed on the training distribution carries no static
guarantee on branch paths never exercised—though when such a path produces an off-type ontology at deployment, the
relevant contract fires and the trace identifies the failing primitive, so the failure is detected and localised rather than
propagating silently.
7 Conclusion
We introduced PLVR, a post-training method that leaves the base model’s weights untouched and instead learns an
explicit program composed from deterministic and neural primitives. Its mechanism, symbolic backpropagation, replaces
the estimated credit assignment of policy-gradient methods with a derivation: given the ontology a layer must produce,
the declared signatures of the primitives induce the ontology the layer below must supply, and typed contracts localise
failure to the step that produced it. Where RLVR verifies a terminal outcome, the reward here is a per-step contract
verdict, dense over the program’s structure. Empirically, the guided search populates a different region of the program
space than uniform sampling over the identical admissible set—a median of 65.6% against 17.5%—rather than merely
reaching the same programs sooner; identification of the best available program is reliable within seventy examples;
and the selected program transfers to unseen examples without the degradation that selection on sixty examples would
ordinarily produce. Two findings run against our own initial expectations and we report them as such: types make
candidates well-formed but do not make the space tractable—the layer-wise beam does—and discovery continues
long after best-in-pool accuracy has plateaued, so a saturating accuracy curve is not evidence that further examples
are worthless. We release the symbolic backpropagation library together with a conformance checker, so that the
method can be applied to any primitive set satisfying the interface. The claim we would most like tested by others
is not a benchmark number but a property of substrates: that running a program- construction procedure over typed,

B.4 Reading the top-3 curve
Top-3 tracks top-1 at a stable 3–4 point deficit in accuracy and a 0.047 deficit in loss from n= 20 onward. This
is the expected direction—pooling three classes admits programs the leading class excludes—and its stability is the
informative part: the leading class is genuinely leading rather than an arbitrary cut, and widening the shortlist buys
coverage at a predictable and modest cost in quality.
The top-3 band is wider than top-1’s at everyn and does not fully collapse, because the third class remains contested
after the first has stabilised. A practitioner carrying a shortlist forward rather than a single program should expect the
shortlist’s composition to keep changing after its leader has settled.
